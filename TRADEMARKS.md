# voidfs name policy

The voidfs code and specs are licensed under Apache-2.0, which lets you use, modify and
redistribute them. As section 6 of that license says, it does not grant rights to the project's
name. This policy says how the name "voidfs" may be used, so that users can tell the project
apart from things built on it.

## You may

- Say that your software **uses**, **is built on**, or **is a fork of** voidfs.
- Say that your server or client is **"compatible with the voidfs protocol, version N"** or
  **"reads and writes the voidfs format, version N"**, provided it passes the
  [conformance suite](spec/conformance/) for that version. Say which cases you skip, if any.
- Use the name in articles, talks, tutorials and packaging that refer to the project itself
  (for example a distribution package named `voidfs` that contains the unmodified project).

## You may not

- Name a fork, a modified distribution, or a product or service "voidfs", or anything likely to
  be confused with it (such as "voidfs Pro" or "voidfs Cloud").
- Imply that the voidfs project endorses, operates or supports your product or service.
- Claim protocol or format compatibility without passing the conformance suite.

If you are not sure whether a use is fine, open an issue and ask.
